# Playground 内化实施计划

> **For agentic workers:** When implementation is authorized, reuse the selected execution method; use superpowers:executing-plans for inline execution or superpowers:subagent-driven-development when delegation is applicable and authorized. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用户能借领域参考检查自己的本体，补全定义，在真实数据上核验后决定是否采用；看图、编辑和学习都在 OntoPoc 本地工作台完成。

**Architecture:** 保留领域定义与企业数据绑定的区别，复用本体库、逐项确认、关系图、核验和问答链路；不另建一套设计器或计算服务。

**Tech Stack:** 现有 Python 本机服务、React/Vite、现有图组件、标准库 RDF/XML 解析与本地文件存储。

## 分轮交付

### 第 1 轮：能浏览参考，读入已有 OWL（#47，待合并）

- [x] 首批本体库、RDF/XML 导入、完整 IRI、来源及未支持内容提示。
- [x] 图固定在可视区，属性独立滚动，说明与原文按需打开。
- [x] 移除工作台常驻汇总排，保留各模块的结果入口。
- [ ] 用户验收并合并 #47；之后新分支从更新的 `origin/main` 创建。

### 第 2 轮：拿领域参考检查自己的本体（建议下一轮）

用户路径：上传数据并建模 → 数据体检 / 对照标准 → 选本体库参考 → 逐项指定对应对象、关系和属性 → 确认本次对应 → 看差异和图中位置。

首个场景：公开 Northwind 客户与订单，对照咖啡零售/电商中的客户、订单及其关系。人可以说明不适用；参考里有而上传数据没有的内容列为待判断，不判作建模错误。

最小实现：先手动映射，沿用已有搜索；本轮不增加模型候选匹配。按完整参考 IRI 和本地对象/关系/字段标识保存对应，记录参考版本与本次运行。相同中文名不自动等同，不能伪造 `populated_from`。

差异按“已对应、仅参考有、仅本次有、约束不同、当前无法检查”展示，不算总分或自设通过阈值。关系方向、角色、属性声明与单位分别呈现；声明的基数与数据核验结果分开。未支持的 OWL 内容明确保持无法检查。

拟落点：

- `ontology_library.py` 提供已有领域定义；新增 `ontology_reference.py` 保存/验证显式映射与差异。
- `ontology_server.py` 接本机映射与比较请求，复用当前运行存储。
- `OntologyStudio.jsx` 的 `ReferenceSection` 接参考选择；`ontologyLibraryModel.js` 与 `OntologyLibrary.jsx` 复用目录显示。
- `ontology_compare.py` 保留原有按来源/名字的对照语义。它目前忽略关系方向，不直接拿来判断领域语义一致，避免影响稳定性等已有调用方。

实施检查项：

- [ ] 新增并先提交 `tests/test_ontology_reference.py`：同名不同 IRI、未确认映射、反向关系、缺属性、不支持约束、改参考版本/改本地对象后的过期映射。
- [ ] 实现确定性映射校验与差异；错误端点、失效字段和重复冲突必须给出可操作的原因，不修改企业本体。
- [ ] 接入现有对照页，映射可取消、修改、重新确认，刷新后能恢复本次已保存的对应。
- [ ] 新增 `landing-page/tests/ontology-reference.test.mjs`：选择参考、指定对应、查看差异和定位、恢复记录；目录/详情仍不需要整页大幅滚动。
- [ ] 用临时数据目录跑 Northwind 真实模型端到端，手工确认映射；独立核对客户/订单关系与数据计算结果，证明比较没有改变原问答答案。
- [ ] 开独立 PR，交用户验收后停止，等待合并。

这一轮不依赖派生指标；需要先合并 #47。若实现中确需 #45 的代码，先报告依赖，不另抄一套。

### 第 3 轮：在逐项确认里补全定义（拆成 3A / 3B 两个 PR）

3A 先做属性：对象已有改名/判定，补字段类型、单位、枚举、说明与绑定编辑，以及本次草稿的撤销重做。用户能从差异进入待补项，看到数据核验结果后决定保存。

3B 再做关系：补关系端点、方向、绑定及基数声明的编辑，检查端点存在、字段可绑定、类型可兼容；约束值由人或明确来源给出。删除对象时列出受影响关系，不悄悄删除。无数据绑定的定义可以保留，但不能冒充可执行查询。

拟落点：`OntologyStudio.jsx` 确认页、`ontologyConfirmModel.js` 草稿、`ontology_confirm.py` 保存校验、`ontology_eval.py` 数据核验、`relation_suggestions.py` 已有关系建议。先复用这些路径，不复制完整 `OntologyDesigner.tsx`。

- [ ] 3A 验收：改单位/枚举后能撤销、重做、取消；核验失败能定位数据原因；未保存草稿不影响问答/导出。
- [ ] 3B 验收：坏端点/失效绑定无法保存；改方向能看出数据与查询影响；不生成任何虚构实例。
- [ ] 两个 PR 各自按失败测试、真实模型、截图验收流程交付。

保存后的查询/导出影响须沿用现有确认规则明确验证。已发布版本的回退与验收退步处理统一交给迭代 9 第 4 轮，不在编辑器再造一个版本体系。

### 第 4 轮：看清对象如何相连

在现有本体关系页选择起点/终点，展示最短结构路径、方向和沿途关系；无路明确提示，不调用模型。支持环、多条等长路径与无连接对象，不把任意遍历结果说成唯一业务路径。

拟落点：`ontologyGraphModel.js` 新增纯图路径函数、`OntologyGraph.jsx` 复用高亮、`OntologyStudio.jsx` 增加选点入口；库中只读参考图复用同一算法。借鉴微软 `PathFinderPanel.tsx` 的操作，不引入第二个图引擎。

- [ ] 在参考图和真实建模图均可找路，图保持可视区内。
- [ ] 图上结构路径标明尚未执行；现有 `pathOf` 继续表达实际问答查询路径。
- [ ] 用公开数据验证一条可计算路径及一条有定义但绑定不足的路径，后者不能显示为已算出答案。

问题 → 路径 → 口径 → 答案 → 补缺口的完整界面属于迭代 9 第 3 轮；本轮只交可复用的找路与高亮。

### 第 5 轮：让新用户完成第一次判断

先做零售订单一个起步任务：看参考 → 了解要准备哪些表 → 上传自己的文件 → 核验客户/订单 → 确认 → 问一个问题。验证可独立走通，再考虑售后工单、产线任务，避免一次铺满模板。

复用 `UploadTab`、本体库与现有示例入口；短说明附在当前动作旁，可跳过、可重开。参考定义不会自动变成人已确认的企业本体，缺字段就明确提示缺口。

- [ ] 取微软分步本体和课程中相关的一小段，保留来源，用我们的任务和界面重写中文引导。
- [ ] 交一份自助起步任务给未参与开发的人；验收是能完成上传、查看核验、确认和提问，不以读完课程或答对概念题为完成。
- [ ] 卡住时只修阻塞这个任务的说明/入口，不扩成课程站或游戏系统。

## 与迭代 9 的衔接

保留 [迭代 9 原计划（#45 分支）](https://github.com/Longado/ontopoc/blob/codex/derived-measures/docs/PRD_ITERATION_9.md)，合并后以主分支该文档为准。

| 迭代 9 剩余轮次 | 接收 Playground 内化产物 | 顺序与边界 |
|---|---|---|
| 第 2 轮：口径 | 属性说明、单位、适用范围的编辑入口 | 类型/枚举是结构声明；业务口径需来源和人确认，不能从参考自动升级为企业事实。 |
| 第 3 轮：问答闭环 | 路径高亮、从缺口进入确认编辑 | 保留真实计算与失败原因，不使用微软预写问答。 |
| 第 4 轮：版本与发布闸门 | 确认的结构变更及参考映射版本 | 统一管理发布和回退；编辑草稿撤销不等于发布版本回退。 |
| 第 5 轮：Agent 按需查询 | 对象、关系、字段、口径及参考来源 | 仅暴露符合原计划的已确认版本，不把整个参考库误当企业可查询对象。 |
| 第 6 轮：记录与改进建议 | 无法映射、缺字段、答不了的具体证据 | 建议仍需人批准，并经过同一发布闸门。 |

建议顺序：合并 #47 → 第 2 轮领域对照 → 第 3A/3B 轮确认编辑 → 第 4 轮路径 → 第 5 轮短引导 → 接回迭代 9 第 2–6 轮。每个 PR 后检查下一轮是否出现 #45 或版本机制依赖；需要提前衔接时先说明，不偷偷扩大本轮。

## 每轮交付与停止点

1. 从更新的 `origin/main` 开新分支；确认上一轮已由用户合并。
2. 写清本轮五行与样本；先运行失败测试并单独提交，再实现。改已有测试前执行 `touch ~/.claude/.allow-test-edit`，规格变化另交提交。
3. 按触及范围跑检查：后端 `PYTHONPATH=src python3 -m unittest discover -s tests`；前端在 `landing-page` 执行 `npm run test:unit`、`npm run test:sites`、`npm run build`；浏览器运行该轮新增的 `node --test tests/<该轮测试>.test.mjs`。
4. 用临时 `--data-dir` 跑一次真实模型端到端。公开数据全量核验在本地完成；沿用现有告知与模型输入最小化，不新增外传，不写出密钥。一次操作串联模型最多 3 步，能用代码判断就不用模型。
5. Headless 截图并实际查看桌面、笔记本和窄屏；详情图不被页面长说明挤走，长列表仅在其区域滚动。
6. PR 写明用户现在能做什么、核验结果与尚未支持的内容；等用户合并。没有真实数据/明确用途的能力先停在计划，不为了追齐微软功能继续扩张。
