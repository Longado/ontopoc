# 已知问题

从 [README](../README.md) 搬来。只属于早期界面（`legacy.html`）的问题在 [LEGACY_SCREEN.md](LEGACY_SCREEN.md#已知问题)。

- **同类对象关系的问答方向尚不支持。** 员工汇报、父子组织等关系可以按两端字段建模、核验和导出；当前问答遍历无法指定上级或下属方向，会说明限制并停止计算。
- **关系检查只要求至少连上一行。** 数据体检里关系那一项，每条关系只要连上一行就算通过，连上的比例很低也一样；页面会写出连上了多少行，请看这个数。
- **定义与连接的范围很窄。** 代码含义只处理一列里的几个取值；重复编号的取法只有三种；表连接只有“输入、连接、输出”三类步骤，连接结果超过行数上限会拒绝运行；名字对算法的检查只认 P50、P90、平均、合计、最大、最小这几类，且需要另一张表里有同名的原始列。以上都只在合成的埋错表和公开数据上试过，没有真实客户数据。
- **值规则的范围很窄。** 一条规则只管一个对象类型（不能跨类型），只写在它自己数据集的属性上（不能写在派生属性上），只有固定几种：不能为空、和一个数比或在两个数之间、是写了含义的代码之一、一个日期不早于同一类型的另一个日期。只能和数比，不能和某个固定日期比；不能写公式，没有规则引擎，每个类型最多 20 条。还不能导出成 SHACL。在一台 Mac 上量过 15 万行、10 条规则：一遍规则检查大约 0.8 秒，在重新检查或一起确认拿写锁之前跑完；只在合成数据上试过。待确认的数字、对象类型列表和待确认列表不在每次打开页面时数规则，用的是类型上次提出、确认或重新检查时存下的数；还在等确认的类型，数据来了新版本后，要有人打开它，才会重新算进待确认的数字（打开时数出来的数会存下）。数规则时读行不拿写锁，但工作区文件用的是 SQLite 的回滚日志，数的时候别人的写入要等它数完才能提交（等数完为止：15 万行、10 条规则量过 0.3 到 0.8 秒，在对象类型页、提出和确认时；改用 SQLite 的预写日志可以免掉这一点，还没做）。
- **旧版本的 OntoPoc 打开有值规则的文件时不认这些规则。** 没有值规则的旧版本能打开这样的文件：改对象类型的名称或说明时规则还在；改主键或属性时规则会被丢掉（类型重新等确认）；上传新数据时不数规则；确认类型时也不看规则。这个版本只在类型最近一次存下的计数是按它现在的数据、现在的规则和代码数的，而且没有一行违反时，才把它的规则当作成立。在那之前，凡是显示或用到这个类型的页面和读出（对象类型列表、对象浏览、看板、问答、智能体的读出、OWL 和 SHACL 下载）都把它显示成“需再看”，不拿它来用。判断这一点时不数任何行；但建设者打开看板或对象浏览页时，仍会把正在等确认的类型的规则数一遍（每次都数），好显示每条规则有多少行不满足。真正去数的时候是：服务启动后（端口打开之后）、有人打开这个类型时、以及第一次有问题或智能体读出要用到它之前。没有可用的计数就数一遍，有规则不满足就退回“需再看”，能确认的人各收到一条消息。数的时候出了错，类型退回并说明值规则没法检查；服务和别的请求照常。
- **一个工作区文件只开一个服务进程。** 数值规则、判断类型在一个进程里一次只做一个；两个进程开同一个文件，可能各自把同一个类型数一遍。
- **答案核对依赖模型如实声明。** 模型说了怎么读定义，代码只核对实际执行的查询有没有用上；模型把读法说错而查询恰好相符时，核对看不出来。查询语言能表达“等于某值”“不是某些值”、数值和日期范围（见 [QUERY.md](QUERY.md)），以及取最高或最低的前 N 个。
- **同一句简单问题，模型可能读成两种。** 比如“销售额是多少？”，模型可能算全部行，也可能只算一个已确认视图，所以两次问到的主数可能不同；模型算全部行、或者按名字用了这个视图时，两个数都会给出；模型自己把视图的条件写出来时，只给出它算的那个数。
- **另称只按写法认。** 带中文的名字或另称，在问题里任何位置出现都算；只有字母的，要作为一个整词出现（英文名的单复数也算）；另称不分大小写和全角半角。写错的字、没人登记成另称的同义词认不出来，这时看模型怎么读。另称只出现在另一个定义更长的名字里时，那一处不算它（演示站上，Customer 的另称“客户”在属性的“客户号”里，不算 Customer）。
- **定义自己的名字落在更长的名字里，照旧算。** 短的那个是名字、不是另称时，永远不会被盖掉：试点数据的类型“客户”在一个属性的另称“客户号”里也算，所以这个类型在等再确认时，“客户号C015的订单有几笔？”会拒答，和主干上名字落在更长的名字里时一样。短的名字还可能落在一个不是任何名字的词里被认出来：这只会多拒答，不会改变数字。本体查询不认另称，类型和关系要写名字或英文名。
- **问题点到了一个视图、模型却没读它，就拒答，即使模型自己写的条件是对的。** 比如“不是有效订单的订单金额合计”，模型排除了已付款、已发货、已送达，仍会拒答，因为问题点到了视图“有效订单”（写名字或另称都算），查询却没有读它；问题同时点到视图和含义、模型按状态分组时也一样。拒答会说明原因；换个不点名视图的问法再问。
- **模型没写进查询的条件，代码发现不了。** 问题要一部分行、模型却没写条件时，回答算的是全部行。
- **“最低”只在有数据的组里排。** 例如“订单金额最低的客户”只排有订单的客户，没下过单的客户不在里面。
- **真实模型的回答会变。** 同一问题多问几次，偶尔会写出代码拒绝的查询（结果是拒答，不是错数）。每轮结束用 `scripts/real_model_check.py` 在内置数据上对照 SQL 跑一遍。
- **“需要再看一眼”按数据占比判断。** 某个值的行数占比翻倍或减半（且至少差 5 行）才算变了，这两个数是定的，不是测出来的；变化小于这个线的错位不会被发现。
- **关系推断的召回有限。** 在 17 份已保存的运行（公开数据与合成数据）上逐条移除关系后重新推断，33 条中找回 24 条；在完整本体上未出现误报。
- **查询能力的限制。** 暂不支持单个问题算两个不同的数（例如同时要合计和平均），以及"哪些项目经常同时出现"一类问题；遇到时系统会如实说明。按数值或日期范围筛选是支持的（[QUERY.md](QUERY.md)）。
- **连接的数据源是复制，不是现查。** 只读连接 PostgreSQL / MySQL 时，拉取是把表复制成数据集的一个新版本（确认要绑定在某一版数据上，所以要复制）；一次最多 50 万行、约 200 MB，只支持这两种数据库。数据要等下一次拉取（手动或调度）才会变。
- **技能包是快照。** “AI 工具接入”页下载的技能包，是下载那一刻已确认定义的副本；之后数据变了、定义退回“需再看”，它不知道，也不会因此拒答。要跟着当前数据拒答，用 MCP 连接。
- **“要回答的问题”是新做的。** 在用脚本代替模型的测试里验证过，2026-11-22 在演示数据上用真实模型跑过一次，用的是修正判定之前的版本（9 个问题，每个问 5 次）。运行开始后在服务里接着跑；服务要是停了，下一次请求会把这次运行记为中途停了，已经发出的调用照算。运行是以跑的人的身份问的，所以只有不受类型名单、列权限、行规则限制的建设者或管理员能跑；行规则会限制所有没被给到全部行的建设者，所以某个类型有行规则时，只有管理员或被这些规则给到全部行的建设者能跑；受限的建设者也看不到清单。比对是精确的（16 和 16.0 一致，1,234.57 和 1,234.5678 不一致），每个问题只比一个数：分组的结果和占比还不能写成期望；期望只记数，不记怎么算的（数正好相等的计数和合计都算通过）。期望拒答时，只有门做出的拒答才算通过（定义没确认或在等再确认、范围里什么都没有、关系走不了、查询漏了已确认的定义、指标在等确认），写了挡住它的定义时还要点名那一个；其他没有数的情况都是“没有回答”。“需要再看”只在回答错了时判断，而且只看期望的回答读过的东西；还没记下这些时（确认在任何一次给出期望回答的运行之前），回答错了就是失败，直到有一次运行通过。结果只在问题还是当时判定时的样子才带着判定显示；问题的文字或期望改了、或者又确认了一次之后，只显示当时答了什么，直到下一次运行。一个工作区文件只能由一个服务来用：同一个文件上开第二个服务进程，会把第一个的运行当成中途停了、把它关掉，还可能在旁边再开一次运行。只改定义的文字也会让它退回等人确认；再确认之后（版本变了）也算期望的回答读过的东西变了，所以之后的一次错数会显示“需要再看”而不是“不一致”；再下一次运行就照常判定。用名字写挡住它的定义时，写的那一刻必须只有一个定义叫这个名字；之后有别的定义起了同样的名字，也会算点到了它，名字可能重复时请写编号。运行存下的句子（拒答的原因）是跑的人当时用的语言。运行不能定时，清单也不能导出。
- **两位建设者都改过同一个定义，要第三位确认或者改回去。** 上次确认之后改过一个定义的人（不论改的是名称、说明还是另称）都不能确认它，已确认的定义被谁改了（包括上次确认它的人）都会退回。所以只有两位建设者时，两人都改过之后谁也不能确认：要另一位建设者来确认（管理员可以加一位），或者其中一位把它改回上次确认的版本，它就自己恢复为已确认（数据在这期间变了的除外）。被拦住的人会看到是谁改过和这几条出路。改回去不会把当初一起退回的东西带回来（读它的关系、视图、派生属性还要再确认）。谁改过记在每个定义上；旧版本写过的文件没有这份记录，那时日志里上次确认之后改过它的人和提出它的人都不能确认。管道仍按自己的规则（上次确认之后保存过步骤的人）。“要回答的问题”的来源说明不算确认的内容：只改它，期望仍是已确认。
- **页面仅在 macOS 上实际用过。** 后端与页面的单元测试在 Linux（CI）上通过；Windows 尚未测试。
