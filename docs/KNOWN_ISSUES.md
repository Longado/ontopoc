# 已知问题

从 [README](../README.md) 搬来。只属于早期界面（`legacy.html`）的问题在 [LEGACY_SCREEN.md](LEGACY_SCREEN.md#已知问题)。

- **同类对象关系的问答方向尚不支持。** 员工汇报、父子组织等关系可以按两端字段建模、核验和导出；当前问答遍历无法指定上级或下属方向，会说明限制并停止计算。
- **关系检查只要求至少连上一行。** 数据体检里关系那一项，每条关系只要连上一行就算通过，连上的比例很低也一样；页面会写出连上了多少行，请看这个数。
- **定义与连接的范围很窄。** 代码含义只处理一列里的几个取值；重复编号的取法只有三种；表连接只有“输入、连接、输出”三类步骤，连接结果超过行数上限会拒绝运行；名字对算法的检查只认 P50、P90、平均、合计、最大、最小这几类，且需要另一张表里有同名的原始列。以上都只在合成的埋错表和公开数据上试过，没有真实客户数据。
- **答案核对依赖模型如实声明。** 模型说了怎么读定义，代码只核对实际执行的查询有没有用上；模型把读法说错而查询恰好相符时，核对看不出来。查询语言能表达“等于某值”“不是某些值”、数值和日期范围（见 [QUERY.md](QUERY.md)），以及取最高或最低的前 N 个。
- **同一句简单问题，模型可能读成两种。** 比如“销售额是多少？”，模型可能算全部行，也可能只算一个已确认视图，所以两次问到的主数可能不同；模型算全部行、或者按名字用了这个视图时，两个数都会给出；模型自己把视图的条件写出来时，只给出它算的那个数。
- **另称只按写法认。** 带中文的名字或另称，在问题里任何位置出现都算；只有字母的，要作为一个整词出现（英文名的单复数也算）；另称不分大小写和全角半角。写错的字、没人登记成另称的同义词认不出来，这时看模型怎么读。问题里同一处，长的名字算数：两个名字里有一个是另称时，“客户号”里的“客户”算属性的，不算对象类型的；两个都不是另称时，短的照旧在长的里面也算。短的名字还可能落在一个不是任何名字的词里被认出来：这只会多拒答，不会改变数字。本体查询不认另称，类型和关系要写名字或英文名。
- **问题点到了一个视图、模型却没读它，就拒答，即使模型自己写的条件是对的。** 比如“不是有效订单的订单金额合计”，模型排除了已付款、已发货、已送达，仍会拒答，因为问题点到了视图“有效订单”（写名字或另称都算），查询却没有读它；问题同时点到视图和含义、模型按状态分组时也一样。拒答会说明原因；换个不点名视图的问法再问。
- **模型没写进查询的条件，代码发现不了。** 问题要一部分行、模型却没写条件时，回答算的是全部行。
- **“最低”只在有数据的组里排。** 例如“订单金额最低的客户”只排有订单的客户，没下过单的客户不在里面。
- **真实模型的回答会变。** 同一问题多问几次，偶尔会写出代码拒绝的查询（结果是拒答，不是错数）。每轮结束用 `scripts/real_model_check.py` 在内置数据上对照 SQL 跑一遍。
- **“需要再看一眼”按数据占比判断。** 某个值的行数占比翻倍或减半（且至少差 5 行）才算变了，这两个数是定的，不是测出来的；变化小于这个线的错位不会被发现。
- **关系推断的召回有限。** 在 17 份已保存的运行（公开数据与合成数据）上逐条移除关系后重新推断，33 条中找回 24 条；在完整本体上未出现误报。
- **查询能力的限制。** 暂不支持单个问题算两个不同的数（例如同时要合计和平均），以及"哪些项目经常同时出现"一类问题；遇到时系统会如实说明。按数值或日期范围筛选是支持的（[QUERY.md](QUERY.md)）。
- **连接的数据源是复制，不是现查。** 只读连接 PostgreSQL / MySQL 时，拉取是把表复制成数据集的一个新版本（确认要绑定在某一版数据上，所以要复制）；一次最多 50 万行、约 200 MB，只支持这两种数据库。数据要等下一次拉取（手动或调度）才会变。
- **技能包是快照。** “AI 工具接入”页下载的技能包，是下载那一刻已确认定义的副本；之后数据变了、定义退回“需再看”，它不知道，也不会因此拒答。要跟着当前数据拒答，用 MCP 连接。
- **页面仅在 macOS 上实际用过。** 后端与页面的单元测试在 Linux（CI）上通过；Windows 尚未测试。
