## 一次上传会发生什么（数据表）

1. 读文件：CSV / Excel（每个 sheet 一张表），自动找表头、跳过标题行，去掉无表头无值的空列。文档走另一条路：Markdown / 文本 / Word / PDF 按段分块，最多 12 块。
2. 起草并核验：模型只看字段名和每列最多 3 个示例值，提出对象、识别字段、关系；代码拿全部数据核验，出错退回重做，最多三次，只有一处都没改掉才提前停。上传前可以展开"看看会发给模型什么"，内容由服务用同一套函数生成。
3. 并行建三次：墙钟时间和建一次差不多。代码按"读同一张表、用同样的识别字段"对齐三次结果，标出不是每次都有的对象和关系（图上画虚线）。文档暂不做。
4. 数据体检（纯代码）：字段去处、同一编号信息打架、编号写法、关系连通、引用能否找到、表的连通、每张表是否真被用上共七项；打架多时按对象和字段汇总，并提示识别字段可能不够区分。文档则核对每条引用是否真在原文里，加"有没有孤立概念"，共两项。
5. 业务问答：一次模型调用把问题写成结构化查询（`start / where / via / group_by / share`），代码在数据上执行。支持多维分组和占比；答不了时分本体缺了、数据里没有、这种问法还不支持三类。最多保留 200 组，同时记下一共多少组。
6. 验收问题（人先定）：把你和客户说定的 1–3 道问题固定下来，存的是人已经看过、认可口径的那个查询（`ontology_acceptance.py`，按 sha256 存在 `output/ontology-runs/acceptance/`）。同一份文件再上传，代码用同样的查询再算一次，只说哪道变了；查询用到的字段没了就停下来指出断点，不猜新含义。模型自己那一轮问答照旧，但"能答几题"本来就会变，不作为验收依据。
7. 逐项确认（人）：在关系图右栏或列表里给每个对象、每条关系点对或不对、改名、补漏，可写确认人。保存后成为这个文件的参考本体（按 sha256 存在 `output/ontology-runs/references/`），马上对照，同一文件以后再上传自动对照并预填上次判断。可下载成带审计信息的参考本体 JSON。

## 已知的边界

- 长文档每次结果差很多：同一份制度、同一个目的连跑 4 次，对象数 111 / 101 / 78 / 116，两次之间差 130–190 处。表格的三次对齐没有覆盖文档。
- 问答的题目每次由模型重出，所以"能答几题"会变；同一道题的答案由代码算，稳定。
- 查询还不能求和、求平均、按数值条件筛选、限定时间段。
- 名称的缩写和改写认不出来（"DEPT OF FLEET MGMT" 与 "DEPARTMENT OF FLEET AND FACILITY MANAGEMENT"）。
- 参考本体里没有关系基数和字段类型。
- 确认和验收问题都按文件 sha256 记忆，客户发来新版文件（哪怕多一行）就对不上，而且不会提示。
- 识别字段如果是"名称"一类会被改写的字段，改名会把一个对象拆成两个；现在只按字段名给提示，没法真正判断。
- 确认改判会归档旧的一份，但页面上还看不到历史。
- 表格和文档还不能在同一个业务问题下一起用。
- 本机网络解析不了国内域名（走 Mullvad 美国出口），中文真实数据表还没试到。

## 名称对应（2026-09-17 加）

数据体检页最后一张卡"两个名字其实是同一个东西"：顾问点一下，代码挑出只按一个名字识别、取值不超过 200 个的对象，把每个取值和它的记录数交给模型一次，模型说哪些指同一个真实事物；代码只保留数据里真有的取值，其余连原因一起列出来。人逐组采纳或撤回，采纳的存进确认过的参考本体，同一份文件下次上传自动带回来。

做了什么：候选、证据（每个写法多少条记录）、模型的一句理由、人的判断、判断的保存与带回。
验证到什么程度：芝加哥合同 3000 行上端到端跑过（提出部门全称与简称两组、采纳、保存、重传带回；重传那次模型只重提了一组，另一组靠上次的确认带回来）。
明确没做：不自动合并任何数据、不改源文件、不做模糊匹配打分或实体解析库；属性列里的同义写法不在射程内（见 `PRD_ITERATION_5.md` 第 8 节）。

## 验收问题与确认的两处补充（2026-09-18 加）

- 问过、且系统明说现在答不了的题，也能记为验收问题。它没有查询可重跑，所以一直算作答不了并计入总数；以后同一道题答出来并被人认可，就替换它。验：芝加哥合同上一道要限定时间段的题和一道求和的题一起固定，清单显示 2 道里能答 1 道。
- 确认会记下当时的建模目的。同一份文件换了目的重传，预填上次判断之前先说明那是为另一个目的判的。验：本机服务的端到端测试（`tests/test_confirm_purpose.py`）。这一轮之前保存的确认没有这条记录。
