# 迭代 8：组织架构模式

## 目标

上传一份公开研究材料（访谈整理、报告、公告），梳理出这家公司的组织：有哪些组织单元、岗位、人、工作环节，彼此怎么隶属、汇报、担任、转任、负责、协作。每条都带原文出处；原文写了时间的带时间；材料明说"不清楚"的地方单独列出。

第一个真实样例：Palantir 产品成熟与团队分工研究（公开访谈与文献）。

## 为什么放在 OntoPoc 里

组织架构是一份词表固定的本体。文档读取、分段、原文核对、逐项确认、关系图、⌘K 搜索、MCP 都能沿用；结果按现有运行的结构存，确认和搜索不用另写。

## 词表（代码写死，模型只能从里面选）

| 类型 | 含义 |
|---|---|
| unit 组织单元 | 公司、事业部、部门、团队 |
| role 岗位 | Deployment Strategist、产品经理、设计师 |
| person 人 | 具名的人，只记工作角色和公开职务 |
| duty 工作环节 | 发现问题、首次实现、通用化、持续运行 |

| 关系 | 两端 |
|---|---|
| part_of 隶属于 | 组织单元或岗位 → 组织单元 |
| reports_to 向…汇报 | 人或岗位 → 人或岗位 |
| holds 担任 | 人 → 岗位 |
| moved_to 转任 | 人 → 岗位或组织单元 |
| responsible_for 负责 | 组织单元、岗位或人 → 工作环节 |
| works_with 协作 | 组织单元或岗位 → 组织单元或岗位 |

## 代码核对

- 每个实体、每条关系的原文摘录必须在该段原文里，找不到就丢掉并写明原因（沿用文档建模的做法）。
- 类型和关系只能是词表里的；两端类型不符合上表的丢掉并写明原因。
- 时间只保留原文里真出现的写法（例如"2019年"），不在原文里的时间删掉，关系本身保留。
- 材料明说不清楚的地方（例如"公开材料仍未说明最终裁决者"）记为"未说明"，同样要有原文摘录。

## 视图

- 组织树：按隶属、汇报排成树，担任某岗位的人挂在岗位下面；没有归属的单独列出。
- 分工矩阵：工作环节 × 负责的组织单元或岗位。
- 时间线：带时间的关系按年份排。
- 未说明：材料里明说不清楚的地方。

## 不做

- 花名册表格、内部文件：内部材料正文要发给模型，等换成本机模型再说。
- 组织图的自由编辑器：改动走逐项确认。
- 从多份材料合并同一家公司：先一份材料一次运行。

## 验收

- 失败测试先交；后端、页面测试全过。
- 用 Palantir 研究汇报跑一次真实模型：组织树里能看到 Echo、Delta、Dev、产品经理与核心产品团队的关系；分工矩阵能对上汇报里"工作环节 × 主要承担者"那张表；每条都能点开看到原文；报告里写明"未说明"的地方出现在未说明清单里。
- 同一份文件按普通文档和组织架构两种模式上传，确认记录互不干扰。
