# OntoPoc 是什么 · 开发方向与边界

这份文档写不常变的东西：OntoPoc 在试什么、站在哪一层、产出什么、一份定义怎么走完一生。现状看 [README](../README.md) 和 [KNOWN_ISSUES.md](KNOWN_ISSUES.md)，开发红线看 `DEVELOPMENT_GUARDRAILS.md`。定位改了就改这份，不要在新文档里重新写一遍。

## 1. 一句话

OntoPoc 是团队数据和回答问题的 AI 之间的确认关口：AI 只按具名同事对着当前数据确认过的定义回答；没确认的，就拒答并说出谁能确认。

拆开说是四件事：

- **定义**：对象类型和主键、代码列的含义（例如状态码 2 = 已取消）、关系、视图（例如“有效订单”）、派生属性。这就是团队的本体（ontology），也就是语义层（semantic layer）里“这个数怎么算”的那部分。
- **对着当前数据检查**：代码在全部行上核主键、连接、扇出、代码取值，检查和看过的行数一起存下。
- **具名的人确认**：提出的人不能自己确认，要另一位建设者确认；确认时记下数据版本和锚点。数据或定义一变，读到它的东西退回“需再看”。
- **回答时看状态**：问答、看板和 MCP 智能体只用这个人看得到的已确认定义；点名了未确认或需再看的定义，在调模型之前就拒答，说出是哪一项、谁能确认。

## 2. 平台部分为什么留、留到哪

一个平台功能只在两种情况下留：关口要它才能工作，或者团队要它才能顺利试用。

| 部分 | 留不留 | 边界 |
|---|---|---|
| 上传 CSV / Excel，数据集版本 | 留 | 确认要绑在“哪一版数据”上；每次上传一个新版本，导入时行数守恒 |
| 只读连接 PostgreSQL / MySQL | 留 | 是复制，不是现查：一次拉取最多 50 万行、约 200 MB，只支持这两种。不加新连接器 |
| 调度 | 留，不再长 | 只为让“当前数据”自己刷新、触发退回；不加新频率，不做编排 |
| 轻管道 | 留，不再长 | 类型常建在管道输出上；不加新算子。逐行问模型的 AI 步骤是实验性的 |
| 血缘、关系图 | 留 | 解释一个定义为什么退回（数据变了、定义改了、上一步过时、更上游过时） |
| 看板 | 留 | 和问答过同一道门：依赖的定义没确认时，给查看者显示“在等”和上次的数；不长图表种类 |
| 行为（批准后写数据） | 收起 | 写数据的动作层不是关口；代码留着，类型没有行为时不显示这个页签 |
| 早期界面（`legacy.html`，按运行建模、口径卡、表单和 Turtle 导出） | 收起 | 读者是实施顾问，不是有数据、要让 AI 回答的团队；代码和地址都在，见 [LEGACY_SCREEN.md](LEGACY_SCREEN.md) |

不做的：重编排、大规模数据、实时查询源库、图表种类上的竞争、执行业务动作写回客户系统。

## 3. 站在哪几层

| 层 | 我们的位置 |
|---|---|
| 语义建模 | 做。人写定义，模型可以提议（建议对象类型、起草代码含义），代码核，另一个人定 |
| 数据映射 | 做，但只到复制进来的数据集：定义绑定到哪个数据集、哪几列 |
| 对象查询 | 做，在复制进来的数据上：OntoPoc Query（[QUERY.md](QUERY.md)）沿已确认的关系走、按提问人的行算；问答让模型写结构化查询，代码执行 |
| 业务逻辑 | 视图（取哪些行）、代码含义（取值是什么意思）、派生属性（一行内的公式或沿关系的统计）。不做规则引擎 |
| 动作执行 | 收起。“行为”的代码还在，不在主路径上 |
| 能力开放 | MCP 的 5 个只读工具（[MCP.md](MCP.md)），令牌就是一个具名的人；技能包是一份快照，数据变了不会拒答。智能体不能上传、写定义或确认 |

## 4. 产出什么，谁用

- **对查看者和智能体**：一个数，旁边写着按哪个口径、谁确认的、哪一版数据；或者一次拒答，说出在等哪个定义、谁能确认。
- **对建设者**：待确认队列、需再看的原因、问题统计（答了、被检查挡下、没算出，以及挡得最多的未确认定义）。
- **留下来的记录**：每次确认的快照（定义、证据、数据版本、提出人和确认人），每个回答连同它用到的定义。

**不是**可执行的运行时契约，也不导出到别的语义层；已确认定义的导出还没有（见 README 的已知问题）。

## 5. 一份定义的一生

提出（人写，或模型提议）→ 代码对着全部行检查 → 另一位建设者确认（记下数据版本）→ 问答、看板、智能体开始用它 → 数据或上游定义一变，退回“需再看”，用到它的问题拒答并说出谁能确认 → 再确认。

最后一环决定这个方向有没有用：数据变了，系统必须说清哪些确认还成立、哪些答案受影响，而不是默默给个新数。

## 6. 说话的规矩

这份文档和所有对外文案里，讲一项能力必须能回答三件事：做没做、验证到什么程度（用什么数据、什么时候、谁核的）、明确没做什么。写不出验证方式的，就算没验证，不能写成已验证。不写“第一个”“唯一”“最好”“领先”。
